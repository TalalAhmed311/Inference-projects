## 1. Experiment design

### Shared-prefix prompts

Prompts live in `experiments/prefix_quant/prompts/`. Every prompt starts with the **same** policy document prefix, then a unique question. That makes vLLM's automatic prefix caching reuse KV blocks for the shared head.

- Shared prefix target: **384** tokens (actual **384**)
- Prompts per size: **32**
- Size **512**: mean tokens **499.0** (file `prompts_512.jsonl`)
- Size **1024**: mean tokens **1005.7** (file `prompts_1024.jsonl`)
- Size **2048**: mean tokens **2039.0** (file `prompts_2048.jsonl`)

Unlike the Stage-0 baseline bench (random unique prompts → ~0 useful prefix hits), this bank is built to **maximize** prefix reuse.

### Quantization variants

| Tag | Model | Scheme |
|---|---|---|
| bf16 | `Qwen/Qwen2.5-1.5B-Instruct` | BF16 weights (baseline) |
| awq | `Qwen/Qwen2.5-1.5B-Instruct-AWQ` | AWQ 4-bit |
| gptq-int4 | `Qwen/Qwen2.5-1.5B-Instruct-GPTQ-Int4` | GPTQ 4-bit |
| gptq-int8 | `Qwen/Qwen2.5-1.5B-Instruct-GPTQ-Int8` | GPTQ 8-bit |
| fp8 | `RedHatAI/Qwen2.5-1.5B-Instruct-FP8-dynamic` | FP8 via compressed-tensors |

Each variant: restart `vllm serve` → warm shared prefix → sweep `input∈{512,1024,2048}` × `output∈{128,256}` × `concurrency∈{1,8,32}`.

## 4. How to read these numbers

- **prefix_hit_pct**: fraction of queried prompt tokens served from the prefix KV cache during that config (`Δhits / Δqueries` from `/metrics`). Higher = less prefill compute.
- **ttft_first vs ttft_rest** (especially at concurrency 1): first request builds the shared prefix; later requests should see lower TTFT when prefix caching works.
- **VRAM peak**: still mostly the reserved pool (`gpu_memory_utilization`). Quantization mainly shrinks **weight** footprint, which can leave more room for KV / higher concurrency on larger models; on 1.5B the absolute savings are modest but still visible.
- **QPS vs tok/s**: longer outputs lower QPS even when token throughput is high.
